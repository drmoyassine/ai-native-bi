# /request

Ask the AMS for something: a feature, a bug fix, a contract change, a field, a route, or a hand-over of code. The issue is
opened HERE (drmoyassine/ai-native-bi) with the label `for-ams`; `.github/workflows/issue-bridge.yml` copies it to drmoyassine/ams (labelled
`from-bi` there) and, when the AMS closes its copy, puts the outcome on this issue and closes it.

## Usage

```
/request <what you need, in a sentence or a paragraph>
```

## Steps

1. Read enough of this repository to state the need precisely (the code, `docs/ams-bi-contract-v0.md` if it touches the contract).
   Do not read the AMS's code to decide how they should build it: say what you need, not how.
2. Write the issue:
   - **Title**: the need in plain words, under 80 characters, e.g. "Supply graduation rate per program for the semester".
   - **Body**, in this order:
     - `## Need`: what, for whom, and why (one short paragraph).
     - `## Contract`: the sections of `docs/ams-bi-contract-v0.md` it touches, or "none". A contract change is always the AMS's
       to make: the BI asks for it with this skill.
     - `## Done when`: one to three checks the other side can verify.
     - `## Hand-over` (only when code or files move): the source paths, the commit SHA they are at
       (`git rev-parse HEAD`), what must change on arrival (imports, package names, tests), and what stays here until the
       receiving side has merged. See "Moving code" below.
     - End with the attribution footer:
       ```

       ---
       _Generated by [Claude Code](https://claude.ai/code)_
       ```
3. Show the title and body to the person and wait for a yes (an issue is outward-facing).
4. Create it with `mcp__github__issue_write` (`method: create`, owner/repo of THIS repository, `labels: ["for-ams"]`). Never open
   it directly in the other repository and never add `from-bi` yourself: the bridge does both.
5. Reply with the link. The bridge's "Sent to ..." comment appears on it within about a minute.

## Moving code

The bridge carries requests, not files. To move a feature between the repositories:

1. **Source side**: `/request` with a `## Hand-over` section (paths + commit SHA). Keep the code here.
2. **Receiving side** (`/inbox`): attach the source repository READ-ONLY to the session (`add_repo`, access `read`), check out the
   named SHA, and port the code into this repository's layout (its packages, imports, tests, conventions). Never copy it
   verbatim without running this repository's checks. Merge it here.
3. **Close the copy** with the commit or PR of the port. The bridge closes the source's issue with that comment.
4. **Source side**: only then remove the code here (its own commit), linking both issues.
